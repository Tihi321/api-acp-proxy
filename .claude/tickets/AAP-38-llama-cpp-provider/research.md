# AAP-38 research: llama.cpp local provider

## Question
What does it take to add a third local server `llama` (profiles `llama/<model>`, one running at a time, auto-switch, per-profile flags, app-downloaded or user-supplied `llama-server.exe`, Hugging Face model download, "Inkling 2 Mini" preset)? Research date 2026-11-21. Code claims are **confirmed** (read) unless marked **inferred**. Web facts were fetched live (URLs given).

## Answer
- Code: Gufo/Strata are two hard-coded ids across ~8 files. `LocalServerManager` already loops over `LOCAL_SERVER_IDS` (generalises by adding an id), but the coordinator host in `main.ts`, the IPC guards, `LocalOpenAiProvider`, the schema, ipc types and the renderer all hard-code `"gufo" | "strata"`. A third id is mostly additive; the Gufo profile UI (`gufoDraft`, `#gufo-profiles`) must be parametrised or copied. No existing code downloads models or picks folders; the Antigravity installer has reusable pieces (download+sha256+progress, zip extraction, zip-slip guard) but its host allowlist, redirect handling and single-file flow need extending; there is no Range/resume.
- llama.cpp releases (BIG GOTCHA): every release is flagged `prerelease: true`, so `GET /releases/latest` returns a stale `v1.0.0` with only `nightly-tag.txt`. Use `GET /releases?per_page=N`, take the first non-draft. Current: **b12606** (2026-11-21). Windows zips are flat (llama-server.exe at root). AMD GPU assets: `win-rocm-10.0-x64` (not "hip-radeon" any more) and `win-vulkan-x64`.
- Inkling 2 Mini exists (thinkingmachines, Apache-2.0, 26.4B MoE, 3.4B active, looped, vision, 1M ctx). BUT mainline llama.cpp gives gibberish until PR #32704, merged 2026-11-21 11:10Z, which is AFTER the newest release b12606 (10:28Z); so no ggml-org release runs it correctly yet. Unsloth's own prebuilt (`unslothai/llama.cpp` b12588-mix-c0c3de8) works. The model has no MTP head; it ships a DSpark drafter (`--spec-type draft-dspark`).
- llama-server health: `/v1/models` is 503 "Loading model" until ready then 200, so the existing probe (`local-servers.ts:57-66`) works unchanged.

## A. Existing code

### A1. Process launcher: `src/local-servers.ts` (confirmed)
- `LOCAL_SERVER_IDS = ["gufo","strata"]` and `LOCAL_SERVER_NAMES` (l.8-9); `LocalServerSpec {id, command, args, cwd, port, profile?, startTimeoutMs?}` (l.11). `commandLine()` = `"<command>" <args>` with `{port}` replaced (l.14-17).
- `checkModelFiles` (l.19-28): regex `PATH_FLAGS = --(model|mtp-model|dspark-model|dflash-model|mmproj)` only; throws `File not found` for absolute paths that do not exist. llama-server flags `-m`, `-md`, `--model-draft`, `--spec-draft-model`, `-mm` are NOT covered; extend the regex (or build args from structured fields and check there).
- Spawn (l.48-55): Windows goes through `cmd.exe /d /s /c "<line>"` hidden; `cwd` must exist (l.120).
- Probe (l.57-66): `GET http://127.0.0.1:<port>/v1/models`, ok = ready. No auth header sent (so do not pass `--api-key` to llama-server, same as today's "apiKey is never put on the command line", ipc.ts:71).
- `start(spec)` (l.116-159): same profile already starting/ready is a no-op (l.124-125); otherwise stops own previous run, then **stops every other server** (l.138-141: `LOCAL_SERVER_IDS.filter(id !== spec.id && running/starting)`), waits for the port to be released (l.143), refuses if the port still answers (l.145). This is the "never together" rule at process level and it extends to a third id with no change. Default start timeout 10 min (l.104), per profile `startTimeoutMs`.
- `stop`, `stopAll`, `close`, log ring (200 lines, ANSI stripped), kill via `killProcessTree` all id-agnostic.
- Constructor creates one entry per id (l.109) so adding `"llama"` to the array is enough for `list()`.

### A2. Coordinator: `src/local-models.ts` (confirmed)
- Single flat namespace of profile ids; `STRATA_PROFILE_ID = "strata"` is a pseudo-profile (l.6-7). `LocalModelTarget = GufoProfile | {id:"strata"}`.
- `LocalModelHost` (l.9-18): `current()`, `start(target)`, `external?(target)`, `waitReady(profile, signal)`. `target(id)` (l.92-94) resolves strata or `getSettings().profiles.find(id)` (Gufo profiles only). Error text says "Unknown Gufo profile" (l.67,129).
- Queue: FIFO, a switch happens only if the active profile has no in-flight request and is not starting (l.115-125); waiter times out with 503 `local_model_busy` after `switchWaitMs` (default 30 min, settings.ts:79); `acquire` = lease for requests, `switchTo` = Settings Start button (no lease). `external()` lets a request pass through to a server the app does not own (l.169).
- To join the rule: the coordinator treats "whichever local server runs" as one thing via `host.current()`. A third server needs (a) llama profiles resolvable in `target()`, (b) a unique key space (see Risks: id collisions with Gufo profile ids; schema currently reserves only `"strata"`, settings.ts:81), (c) host callbacks that know the third id.

### A4. Provider: `src/providers/local-openai.ts` (confirmed)

Use `GET /releases?per_page=30` (unauthenticated limit 60 req/h; response is ~1 MB per 100; use per_page small) and choose the first entry with `draft == false` that has the wanted asset. Cache the result; send `User-Agent`.

## C. llama-server flags (confirmed from https://raw.githubusercontent.com/ggml-org/llama.cpp/master/tools/server/README.md and docs/speculative.md; flag names are from a build newer than b12606 master)
- Model: `-m, --model FNAME`; `-hf <user>/<model>[:quant]` (server downloads itself, default Q4_K_M, mmproj auto) l.104; `-hft` token.
- `-c, --ctx-size N` (0 = from model) l.50; `-ngl, --gpu-layers N|auto|all` (default auto) l.85; `-fa, --flash-attn on|off|auto` (default auto) l.56; `-np, --parallel N` (default auto) l.178.
- `--jinja` is **enabled by default** (`--jinja/--no-jinja`) l.239; `--chat-template-file`, `--chat-template-kwargs`; reasoning: `-rea, --reasoning on|off|auto`, `--reasoning-format`, `--reasoning-effort`, `--reasoning-budget` l.240-244 (reasoning arrives as `reasoning_content`, which the provider already forwards, local-openai.ts:164).
- Vision: `-mm, --mmproj FILE` l.180; `--no-mmproj`, `--mmproj-offload`.
- Server: `--host` (default 127.0.0.1) l.194, `--port` (default **9931**) l.195, `-a, --alias` l.191, `--api-key`, `--models-dir` (router mode) l.234.
- Speculative decoding (flags were renamed; old names are errors): `--spec-draft-model, -md, --model-draft FNAME` l.280; `--spec-draft-n-max N` (old `--draft-max`, now "removed") l.269,294; `--spec-draft-n-min` l.270 (`--draft-min` removed l.295); `--spec-draft-ngl, -ngld, --n-gpu-layers-draft N` l.279; `--spec-draft-hf, -hfd` l.254; `-devd`; `--spec-default` l.312 (default spec config); `--spec-type none,draft-simple,draft-eagle3,draft-mtp,draft-dflash,draft-dspark,draft-dflash2,draft-lilicorr,ngram-simple,ngram-map-k,ngram-map-k4v,ngram-mod,ngram-cache` l.281. Because flags are renamed across versions, **args must be generated against the installed build** (or users edit raw args); pin `--spec-draft-*` names to the version range and warn when a user-pointed exe is older.
- MTP: supported as `--spec-type draft-mtp` ("MTP heads from the main model", docs/speculative.md l.423) and `--mtp` ("also download the MTP head if available", common/arg.cpp l.3090-3093, implies draft-mtp). MTP support is added per architecture (merged PRs e.g. #29761 Qwen4Exp MTP, #29928 GLM5Next MTP, #30612 Mellum2.1 MTP). With `-hf`, an MTP sidecar GGUF is auto-resolved (arg.cpp l.553-662); with local files an MTP head is passed through `-md` + `--spec-type draft-mtp` (**inferred** from arg.cpp l.593-599: the discovered head is assigned to `speculative.draft.mparams.path`). Which models: only those whose architecture has MTP wired; no static list in the README.
- Health: `GET /health` (also `/v1/health`) public, 503 `{"error":{"message":"Loading model"}}` while loading, 200 `{"status":"ok"}` when ready (README l.486-497). `GET /v1/models` is behind the same readiness middleware (server-http.cpp l.392-412: all non-frontend paths give 503 "Loading model" until ready) and behind the API key if one is set. => keep `/v1/models` probe. Both `/health` and `/v1/models` are fine; `/health` is not key-protected (better if a key is ever used).
- Router mode (README l.2064-2172, 2388): `llama-server --models-dir <dir> --models-max 1` loads/unloads models on demand per request by `model` name, with `--models-preset` INI per-model args. This is a possible **alternative design** to the app-managed profile switching (one process, llama.cpp does the switching), but it conflicts with the user's decision (profiles with flags, one running at a time, app-controlled) and with the coordinator's lease logic; mention only.

## D. Hugging Face (confirmed via live API calls, 2026-11-21)
- Link forms to parse: `https://huggingface.co/<owner>/<repo>` (repo), `.../blob/<rev>/<path>` and `.../resolve/<rev>/<path>[?download=true]` (file), `<owner>/<repo>:<QUANT>` shorthand (as llama.cpp `-hf`; quant case-insensitive, default Q4_K_M, falls back to first GGUF, README l.104), also `hf.co/...`. Path may be nested (`Q4_K_M/xxx-00001-of-00006.gguf`).
- Listing: `GET https://huggingface.co/api/models/<repo>/tree/main?recursive=true` returns `[{type:"file"|"directory", path, size, lfs?}]`, with real byte sizes for LFS files (no `?blobs` needed), e.g. `Inkling-2-Mini-UD-IQ4_XS.gguf 15.73 GB lfs`. Directories appear when not recursive. Large repos paginate (Link header; follow it). `GET /api/models/<repo>` gives `gated` (false/"auto"/"manual"), `siblings`, `cardData.license`.
- File download: `GET https://huggingface.co/<repo>/resolve/<rev>/<path>` -> 302 to a CDN host (observed `us.aws.cdn.hf.co/xet-bridge-us/...` with signed query). The CDN answers `Accept-Ranges: bytes`; the 302 carries `X-Linked-Size` (= file size) and `X-Linked-ETag`. Resume = `Range: bytes=<partial size>-` on the resolved URL (send `If-Range` with the ETag optionally; re-resolve the redirect on expiry because the signed URL expires). Redirect hosts must be allowlisted by suffix (`huggingface.co`, `hf.co`); do not forward `Authorization` to the CDN host.
- Split GGUFs: `<name>-0000N-of-0000M.gguf`; llama.cpp loads from the first shard if all shards sit in the same folder. Detect with `/-(\d{5})-of-(\d{5})\.gguf$/`, list all M shards, download all, set `-m` to shard 1 (confirmed examples: `unsloth/Qwen3-Coder-480B-A35B-Instruct-GGUF/Q4_K_M/...-00001-of-00006.gguf`).
- mmproj: separate files named `mmproj-*.gguf` in the repo root (unsloth: `mmproj-BF16/F16/F32.gguf`, 0.64-1.27 GB; ggml-org: `mmproj-Inkling-2-Mini-BF16/Q8_0.gguf`). Offer as an optional extra download tied to a profile with `vision: true`.
- Gated repos: `meta-llama/Llama-3.2-1B-Instruct` has `gated: "manual"`; the tree API answers 200 anonymously but `/resolve/` returns **401** without a token. Needs a user HF token (Bearer, `Authorization: Bearer hf_...`), stored like other secrets (`mapSecrets`, settings.ts:234) and sent only to `huggingface.co` (not CDN). A 403 after auth = terms not accepted on the website.
- Disk: models of 8-28 GB; check free space on the target drive before starting (`fs.statfs`, Node >= 18.15) and write to `<file>.partial`, rename on completion, optional sha256 check against the LFS `oid`/ETag.
- Unsloth quirk: `Mainline_Support/*.gguf_file` (extension intentionally `.gguf_file`; must be renamed to `.gguf` after download).

## Risks
- **Inkling 2 Mini does not work on any current ggml-org release** (fix merged after b12606); a preset marked ready would produce gibberish or load errors. Needs min-build gating or pointing at Unsloth's prebuilt; or ship the preset later. Today's date is the same day as the merge, so it may be resolved within hours: re-check `GET /releases?per_page=3` and the commit list.
- `/releases/latest` unusable (prerelease-only); rate limit 60/h unauthenticated; the 12 builds/day cadence means "latest" changes constantly and flag names change (draft flags already renamed/removed). Pin by tag; keep raw-args escape hatch; warn on user-supplied old exe.
- ROCm zip covers specific gfx targets (RDNA1-4 listed); other AMD GPUs must use Vulkan; I could not verify which the user's GPU needs. Zip layout inferred, not listed.
- Security: downloading and running binaries (unsigned; sha256 only proves integrity vs the GitHub digest) and HF files; strict host allowlist across redirects, never send the HF token to non-HF hosts, zip-slip guard (`safeEntryPath`), extraction size cap (2 GiB cap at antigravity-installer.ts:13 is too small for the ROCm/CUDA zips + cudart if limit is applied per archive: ROCm zip 285 MB compressed; uncompressed unknown, raise the cap).
- Disk and time: 8-28 GB downloads, drive D: space, partial files, interrupted app (resume), concurrent installs (single-flight like `installing`), anti-virus locking when renaming extracted dirs (the installer already retries only settings writes).
- Coordinator id collisions between Gufo and llama profile ids (flat id space, `target()` finds by id across a single list); reserved-id check currently only for `strata`.
- Start timeout: default 10 min is fine for llama; large models load slower on HDD. `start()` refuses when something already answers on the port; default llama port must not collide with 8080/8081 or the proxy 8787.
- `checkModelFiles` only validates flags in `PATH_FLAGS`, so a missing GGUF otherwise shows as a process exit with the last log line.
- `/v1/models` probe needs no key; if the user sets `apiKey` for llama it would break the probe and the app never passes it on the command line (existing behaviour for Gufo/Strata, so the key field is for external servers only). Decide whether llama gets an `apiKey` field.
- Tests that enumerate ids (`local-servers.test.ts:43`, `controller.test.ts:60`) will need updating.
- Provider is text/vision only: no tools, no MCP, no web search (local-openai.ts:96); llama-server supports tools natively (jinja) but the provider declares `tools:false`, so Inkling's agentic strengths stay unused; out of scope but worth stating.
